  question="يظهر أمر df -h أن القرص ممتلئ بنسبة 100%، بينما يظهر أمر du -sh أن المساحة المستخدمة لا تتعدى 20%. ما هو السبب الجذري وكيف تحله دون إعادة تشغيل الخادم؟"
  directAnswer="السبب هو وجود ملفات تم حذفها باستخدام أمر rm، ولكنها لا تزال مفتوحة ومحتجزة بواسطة عمليات قيد التشغيل (مثل خادم تطبيقات يكتب في ملف سجل محذوف). يقوم نظام الملفات بفك الرابط الاسمي فقط للملف، لكنه لا يحرر كتل البيانات (Blocks) على القرص طالما واصف الملف (File Descriptor) مفتوح. يتم حل المشكلة باستخدام lsof +L1 للعثور على المعرفات PIDs المحتجزة، ثم تفريغ الملف بكتابة > /proc/<PID>/fd/<FD> أو إعادة تشغيل الخدمة المسؤولة."
  pitfalls={[
    "إعادة تشغيل أمر rm مرارًا وتكرارًا على أمل تحرير المساحة؛ الملف غير مرئي في شجرة المجلدات أصلاً لأن مدخله الاسمي أُزيل.",
    "إعادة تشغيل الخادم بالكامل كحل سريع بدلاً من تشخيص وحل تسريب واصفات الملفات في العملية المعنية."
  ]}
  followUps={[
    "كيف يمكنك قراءة محتويات ملف محذوف لا يزال مفتوحًا بواسطة عملية عبر مسار /proc؟",
    "كيف تقوم بتفريغ ملف سجل ضخم في الإنتاج دون كسره عبر أمر truncate أو > access.log؟"
  ]}
>
خطوات التشخيص والحل في بيئات الإنتاج:

1. **اكتشاف العمليات التي تحتجز ملفات محذوفة:**
   ```bash
   lsof +L1
   # أو فحص العمليات التي تحتفظ بملفات محذوفة (deleted)
   lsof | grep '(deleted)'
   ```
   ستظهر لك العملية (مثل `nginx` أو `java`) مع الـ `PID` وحجم الملف وواصف الملف `FD`.

2. **تحرير المساحة فوريًا دون إيقاف الخدمة:**
   يمكنك تفريغ محتوى الملف المحتجز مباشرة من خلال الرابط الوهمي في `/proc`:
   ```bash
   > /proc/<PID>/fd/<FD_NUMBER>
   ```
   هذا يفرغ كتل البيانات في القرص فورًا ويجعل المساحة حرة في `df -h` دون الحاجة لإعادة تشغيل أو قطع الاتصال بالخدمة.

3. **إعادة تشغيل أو إعادة تحميل الخدمة بنظافة:**
   ```bash
   systemctl reload <service-name>
   ```
</InterviewQuestion>

  directAnswer="الرابط الصلب (Hard Link) هو اسم إضافي يشير إلى نفس رقم الـ Inode ونفس كتل البيانات على القرص؛ إذا حذفت الملف الأصلي يبقى الرابط الصلب يعمل بكامل محتواه، ولا يمكن إنشاء روابط صلبة للمجلدات أو عبر أنظمة ملفات مختلفة. بينما الرابط الرمزي (Soft Link) هو ملف منفصل تمامًا يملك Inode خاص به ويحتوي فقط على المسار النصي للملف المستهدف؛ إذا حُذف الملف الأصلي يُكسر الرابط (Broken Link)، ويدعم الإشارة للمجلدات وعبر أقسام وأنظمة ملفات مختلفة."
  pitfalls={[
    "محاولة إنشاء Hard Link بين قسمين مختلفين (مثل بين / و /var على قرص منفصل)، وهو أمر مستحيل لأن أرقام الـ Inodes فريدة ومستقلة لكل نظام ملفات.",
    "الاعتقاد بأن تعديل محتوى Soft Link لا يغير الملف الأصلي؛ التعديل على أي رابط يغير محتوى الملف الفعلي، ولكن حذف الـ Soft Link يحذف الرابط فقط."
  ]}
  followUps={[
    "ماذا يمثل العمود الثاني في مخرجات أمر ls -l؟",
    "متى تقوم النواة بحذف كتل بيانات الملف الفعلي (Blocks) نهائيًا من القرص؟"
  ]}
>
جدول المقارنة الجوهري:

| وجه المقارنة | Hard Link (الرابط الصلب) | Soft / Symbolic Link (الرابط الرمزي) |
|---|---|---|
| **رقم الـ Inode** | نفس رقم Inode الملف الأصلي | يمتلك رقم Inode جديد ومستقل |
| **عبور أنظمة الملفات** | لا يمكن (نفس الـ Filesystem حصراً) | نعم (يمكن الربط عبر أي مسار وقسم) |
| **الربط بالمجلدات** | غير مسموح به (لمنع الحلقات اللانهائية) | مسموح به بالكامل |
| **تأثير حذف الملف الأصلي** | يبقى الملف متاحاً عبر الرابط دون أي فقد للبيانات | يُكسر الرابط ويصبح مؤشراً لمسار مفقود (Dangling Link) |
| **أمر الإنشاء** | `ln file link` | `ln -s file link` |
