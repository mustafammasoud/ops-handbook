المقارنة التقنية بين الحالتين:

- **العملية اليتيمة (Orphan Process):**
  - الحالة: الأم ماتت، والابن لا يزال يعمل.
  - المعالجة: تقوم النواة بنقل تبعية العملية إلى `PID 1` (Systemd) في عملية تسمى **Re-parenting**.
  - الخطورة: صفر؛ النظام يديرها بشكل طبيعي.

- **العملية الشبح (Zombie / Defunct Process):**
  - الحالة: الابن انتهى (استدعى `exit()`)، لكن الأم لم تستدعِ `wait()` أو `waitpid()`.
  - الموارد المستهلكة: لا تستهلك CPU أو RAM، ولكنها تحتجز **PID** في جدول عمليات النواة.
  - كيفية التخلص منها:
    ```bash
    # 1. معرفة العملية الشبح والأب الخاص بها
    ps -eo pid,ppid,stat,cmd | grep '[Zz]'

    # 2. إرسال إشارة تنبيه للأب لقراءة خروج الأبناء
    kill -s SIGCHLD <PPID>

    # 3. إذا لم يستجب الأب، يجب إنهاء الأب نفسه ليتبنى PID 1 الأشباح وينظفها
    kill -15 <PPID>
    ```

جدول الإشارات الأكثر استخدامًا في بيئات DevOps:

| رقم الإشارة | الاسم | المعنى والسلوك | هل يمكن للتطبيق التقاطها؟ |
|---|---|---|---|
| `1` | `SIGHUP` | قطع الاتصال بالطرفية / إعادة قراءة ملفات التكوين (Reload) | نعم (Catchable) |
| `2` | `SIGINT` | المقاطعة اليدوية من لوحة المفاتيح عبر `Ctrl+C` | نعم (Catchable) |
| `9` | `SIGKILL` | إنهاء فوري إجباري تنفذه النواة مباشرة | **لا (Uncatchable)** |
| `15` | `SIGTERM` | طلب الإغلاق السلس المؤدب (Graceful Termination) | نعم (Catchable) |
| `17 / 18` | `SIGCHLD` | إشعار من الابن المنتهي إلى الأب | نعم (Catchable) |

**الممارسة الاحترافية الموصى بها:**
أرسل `SIGTERM` أولاً، وانتظر مهلة زمنية (مثل 15 أو 30 ثانية)، وإذا استمرت العملية في التعليق، استخدم `SIGKILL` كملاذ أخير:
```bash
kill -15 <PID>
# انتظار للإغلاق النظيف
sleep 10
kill -0 <PID> 2>/dev/null && kill -9 <PID>
```
