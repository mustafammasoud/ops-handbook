<InterviewQuestion
  id="git-reset-soft-mixed-hard-vs-revert"
  number={1}
  difficulty="intermediate"
  tags={["git", "recovery", "reset", "revert"]}
  question="Compare the three git reset command levels (--soft, --mixed, and --hard), and what is the fundamental difference between Reset and Revert?"
  directAnswer="git reset moves the branch pointer to a previous commit with differences in where changes are saved: --soft moves modifications to the Staging Area, --mixed (default) moves modifications to the Working Directory and unprocesses them, and --hard permanently clears modifications from all locations. The key difference: Reset rewrites history by deleting commits and is only valid for local branches, while Revert creates a new commit that completely safely mirrors and undoes the impact of a previous commit for shared global branches."
  pitfalls={[
    "Using git reset --hard on a branch that has been pushed to a remote repository and then trying to force a push can wipe out the team's work.",
    "The belief is that git reset --hard deletes everything irreversibly; lost commits can often be recovered via git reflog if the repository is not cleaned via Garbage Collection."
  ]}
  followUps={[
    "How do you use the modern git restore command to undo modifications to a specific file instead of using the old git checkout?",
    "What happens if I git revert a Merge Commit?"
  ]}
>
`git reset` levels table:

| The command | HEAD index and branch | Preparation area (Index / Stage) | Working Tree folder
|---|---|---|---|
| `git reset --soft <hash>` | Moves backwards | **Modifications remain ready** | The modifications remain
| `git reset --mixed <hash>` (default) | Moves backwards | **Equipments are canceled (Unstaged)** | The modifications remain
| `git reset --hard <hash>` | Moves backwards | **Modifications are deleted** | **Modifications are completely deleted** |

**When do you use Revert versus Reset?**
- **Local Feature Branch:** Use `git reset` if you want to undo your recent commits and refactor them cleanly.
- **Shared `main` or Production):** Use `git revert <commit-hash>` exclusively:
  ```bash
  # Creates a new commit that accurately undoes changes to the previous commit without touching the old history
  git revert 3a4b5c6
  ```
</InterviewQuestion>

<InterviewQuestion
  id="git-reflog-detached-head-rescue"
  number={2}
  difficulty="advanced"
  tags={["git", "recovery", "reflog", "detached-head"]}
  question="What is the case of Detached HEAD, and how can git reflog rescue lost commits after a false reset?"
  directAnswer="Detached HEAD state means that the HEAD pointer points directly to a specific commit hash instead of pointing to a branch name. If you write new commits in this state and then move to another branch, those commits become suspended (Orphaned/Unreachable). The git reflog records every move the HEAD pointer made locally, enabling you to find the missing hash and create a new branch that installs it immediately."
  pitfalls={[
    "Moving to another branch (such as git checkout main) after committing modifications is in Detached HEAD state without naming the branch, making modifications invisible in git log.",
    "Belief that git reflog is available on a remote server; the reflog is a purely local personal log and is not uploaded to GitHub."
  ]}
  followUps={[
    "How long does the default log remain in git reflog before git gc deletes it?",
    "How do you recover a local branch that was accidentally deleted via git branch -D command?"
  ]}
>
Rescue scenario via `git reflog`:

1. You made a critical commit in `Detached HEAD` state or you did a wrong `git reset --hard`.
2. The commit disappeared from `git log`.
3. Run the reference transaction log:
   ```bash
   git reflog -n 10
   ```
   The output will show previous cursor movements:
   ```
   a1b2c3d HEAD@{0}: reset: moving to HEAD~3
   f4e5d6c HEAD@{1}: commit: important emergency fix
   9876543 HEAD@{2}: checkout: moving from main to detached HEAD
   ```
4. Create a new branch that installs this commit immediately before the memory cleaner deletes it:
   ```bash
   git branch recovery-branch f4e5d6c
   ```
Now all files and commits have been recovered successfully and safely.
</InterviewQuestion>
