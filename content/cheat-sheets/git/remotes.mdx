## 1. Remote Repositories and Synchronization

<Callout type="warning" title="Avoid traditional Force Push">
Always use `--force-with-lease` instead of regular `--force`, as the former checks for new commits pushed by your colleague before replacing the date.
</Callout>

<CheatSheet
  rows={[
{
      command: 'git remote -v',
      does: 'Displays the names and addresses of the remotes registered for the repository (fetch and push)',
      when: 'to check the associated remote servers',

    {
      command: 'git remote add origin <url>',
      does: 'Link the local repository to a new remote repository named origin',
      when: 'When a new local repository is uploaded to GitHub for the first time',
      example: 'git remote add origin git@github.com:user/repo.git',
    },
    {
      command: 'git fetch origin',
      does: 'Fetch all updates and branches from remote without merging them into your local branch',
      when: 'To see what is new on the server safely and without surprises',
      example: 'git fetch origin',
    },

command: 'git pull',
      does: 'Fetches updates and automatically merges them into the current branch',
      when: 'to update the regular local branch',
      example: 'git pull',
    },
    {
      command: 'git pull --ff-only',
      does: 'Fetch and update the branch only if it can be Fast-Forward updated without creating a merge commit',
      when: 'To maintain the cleanliness and integrity of the history of the local branch',
      example: 'git pull --ff-only',
    },

      command: 'git pull --rebase origin main',

      when: 'before payment to avoid unnecessary merge commit',

    },

      command: 'git push',

      example: 'git push',
    },

      when: 'When a new branch is first pushed to the remote',

    {

      example: 'git push --force-with-lease origin feature/login',
