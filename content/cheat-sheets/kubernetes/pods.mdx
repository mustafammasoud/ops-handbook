## 1. Pod Management & Inspection

<Callout type="tip" title="Filtering namespaces">
Use the flag `-A` or `--all-namespaces` to display Pods across the entire cluster, or `-n <namespace>` to focus on a specific namespace.
</Callout>

<CheatSheet
rows={[
    {
      command: 'kubectl get pods -A',
      does: 'Displays all running Pods across the entire namespaces in the cluster',
      when: 'To get a quick overview of the health of services across the cluster',
      example: 'kubectl get pods -A -o wide',
    },
    {
      command: 'kubectl get pods -n <ns> -w',
      does: 'Monitors the status of the Pods in real time and prints the changes as they occur (Watch mode)',
      when: 'While deploying a new update or while monitoring a disabled Pod restart',
      example: 'kubectl get pods -n production -w',
    },
    {
      command: 'kubectl describe pod <pod-name> -n <ns>',
      does: 'Displays comprehensive details about the Pod, including recent events and statuses of installed containers and drives',
      when: 'When encountering CrashLoopBackOff or ImagePullBackOff conditions to find out the cause of the failure in the Events section',
      example: 'kubectl describe pod api-server-79bbd8f-4x9zq -n production',
},
    {
      command: 'kubectl logs <pod-name> -f -n <ns>',
      does: 'Prints the container logs inside the Pod and follows the live broadcast of the logs (-f /follow)',
      when: 'to track requests or diagnose errors while the application is running',
      example: 'kubectl logs web-service-7db5c -f -n production',
    },
    {
      command: 'kubectl logs <pod-name> -p -n <ns>',
      does: 'Displays the logs of the previous version of the container that crashed just before it was restarted (-p /previous)',
      when: 'When the application quickly crashes and restarts without the ability to read the live log',
      example: 'kubectl logs crash-service-xyz -p -n production',
    },
    {
      command: 'kubectl exec -it <pod-name> -n <ns> -- /bin/sh',
      does: 'Opens an interactive terminal session inside the Pod container to execute direct commands',
      when: 'to test the internal network or examine configuration files and environments inside the container',
      example: 'kubectl exec -it redis-master-0 -n database -- sh',
},
    {
      command: 'kubectl port-forward pod/<pod-name> <local>:<remote> -n <ns>',
      does: 'Forward a port from your local device directly to a specific port within the Pod in the Cluster',
      when: 'To access internal service and development databases without creating an Ingress or LoadBalancer',
      example: 'kubectl port-forward pod/postgres-0 5432:5432 -n database',
    },
    {
      command: 'kubectl delete pod <pod-name> -n <ns> --grace-period=0 --force',
      does: 'Force the cluster to delete the Pod immediately without waiting for a soft shutdown (Force delete)',
      when: 'When the Pod gets stuck in a Terminating state due to a problem with the node',
      example: 'kubectl delete stuck pod-pod-99 -n default --grace-period=0 --force',
    },
  ]}
/>
